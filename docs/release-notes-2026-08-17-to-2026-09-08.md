**Datex Agent Skills release notes — August 17–September 8, 2026**

This update expands the guidance for building Datex Studio applications and working with Footprint WMS. The main changes are owned datasources by default, more complete datasource validation guidance, index-aware query design, improved Custom Angular Component workflows, and broader authoring and evaluation coverage.

These notes describe changes to the skills, reference documentation, and bundled tooling; CLI and platform behavior is documented here but ships in separate repositories. No new standalone skills were added during this period.

- **Datasources are now owned by default.** When a grid, editor, form, or report needs a datasource, the authoring skills keep it with its host. Standalone datasources remain appropriate for an actual second consumer, a consumer that cannot embed one, dependencies called from flow code, or library distribution. The datasource skill now reports the selected mode and explains any standalone override. ([#53](https://github.com/datex/skills/pull/53))

- **Owned datasource creation and wiring are documented end to end.** New instructions cover generating a flow datasource, embedding it in a grid/editor/form, mirroring the host's contracts, adding a grid's `totalCount` output, and validating the host. Reports retain their separate manifest-based registration workflow. Reference resolution is clarified: `isOwned: true` selects the embedded lookup, and `configId` must match the embedded datasource's `referenceName`. Tailored references preserve their existing `moduleId` because it participates in overlay identity. ([#50](https://github.com/datex/skills/pull/50), [#52](https://github.com/datex/skills/pull/52))

- **Flow datasource guidance now covers three execution shapes.** Single-result, unkeyed collection, and keyed collection shapes are mapped to their consumers and generated methods. Grids and selectors need keyed collections; lists and calendars can use unkeyed collections; editors and datasource-backed forms need a single result. Linked datasource guidance now maps `oneToOne`, `oneToMany`, and `oneToOneWithMerge` to the corresponding contracts. ([#28](https://github.com/datex/skills/pull/28), [#43](https://github.com/datex/skills/pull/43))

- **Datasource validation guidance matches the separate usage and isolation gates.** The skills explain why validating a datasource alone cannot prove that its consumer is wired correctly, and why malformed datasources can block publishing even without a consumer. Missing required collection flow slots are documented as errors; a legacy extra `getFlow` on a collection is advisory. Forms also gain checks for missing owned datasources and empty reference objects, with a true `null` required when no datasource is bound. ([#43](https://github.com/datex/skills/pull/43))

- **Query design now includes index checks and required scoping.** Schema exploration documents `indexes`, `describe-index`, index details on `describe-entity`, and batch queries. Guidance distinguishes leading key columns, included columns, and unavailable metadata. Datasource authoring also addresses generated filter guards: an omitted parameter can remove the predicate that bounds a query, and `--detect-params` can guard an entire composite filter. Authors are given explicit ways to preserve the required scope. Index commands require a CLI build newer than 0.5.5 and a server that exposes index metadata. ([#46](https://github.com/datex/skills/pull/46))

- **OData authoring references address additional runtime failures.** Updated examples use object-shaped `selects`, distinguish input and output parameter descriptors, and require output metadata that generates usable datasource methods. New guidance covers formatter-provided escaping and delimiters, unsupported conditional sort entries, root correlation through `$it`, and empty strings that disappear from `in` filters. The docs identify CLI 0.4.17 as the minimum for generating the current `selects` shape. ([#29](https://github.com/datex/skills/pull/29), [#31](https://github.com/datex/skills/pull/31))

- **Custom Angular Component synchronization and cleanup use the CLI lifecycle.** The skill distinguishes `preview --refresh`, which preserves local authoring work, from `pull --force`, which replaces the working folder from Studio. It documents restoring mocks and manifest dependencies after replacement, using `preview --clean` to reset preview state, and calling `dxs ng stop` when finished. Troubleshooting now separates compile failures, browser capture failures, and datasource connection preflight failures. ([#29](https://github.com/datex/skills/pull/29))

- **Custom Angular Component prerequisites no longer require localhost or a Development API.** The final guidance requires a reachable, authenticated Datex API for the target branch. It clarifies that harness generation for `create` and `pull` works against configured development, QA, or production APIs, separately from the environment restrictions on application publishing. This correction was merged on September 8. ([#45](https://github.com/datex/skills/pull/45))

- **Grid authoring guidance addresses performance, refresh timing, and styling.** New rules place `$row` handlers in `rowFlows`, move backend work out of per-row load handlers, and keep filter-state writes synchronous when they must precede refresh. References also document column sizing, live toolbar labels, dynamic filter/sort accessors, button-cell icons, the distinction between cell and control styling, and scoping injected CSS to its component. ([#31](https://github.com/datex/skills/pull/31))

- **Forms, editors, hubs, and selectors gain more precise contracts.** Editor guidance separates `formValidationFlows` from ordinary flows to avoid duplicate generated methods. Form guidance uses native dropdown multi-selection. Selector references explain numeric custom-option values and require `getByKeysFlow` to be self-contained, read-only, and faithful to the requested keys. Hub-local flows are documented without input parameters, while dynamic labels use declared host variables. ([#31](https://github.com/datex/skills/pull/31))

- **Shared references now cover cards, lists, frontend flows, and scheduled jobs.** New documentation describes component skeletons, datasource and event wiring, dialog invocation, frontend flow dispatch, keyboard and toast behavior, and cross-package dialog resolution. Background job guidance covers submission, recurring schedules, concurrency, idempotent initialization, and enable/disable lifecycles. These are reference additions within the existing shared/runtime skills. ([#31](https://github.com/datex/skills/pull/31))

- **Function and action guidance captures failures beyond declarative validation.** References now cover keeping action code mirrors synchronized, returning declared flow outputs on early exits, initialization hazards after a final return, and fresh state on every invocation. They also document dispatch costs, nested parent/child creation, HTTP URL differences between execution tiers, date utility argument order, and preserving JSON strings when storing structured content. ([#31](https://github.com/datex/skills/pull/31))

- **Storage and backend test guidance is more complete.** The `$db` reference corrects `.add()` to return an ID string, expands querying and mutation APIs, and documents empty-storage reads, ignored null patches, atomic claims, and the absence of multi-write transactions. Backend test suites now route storage access through same-package functions or a test-support function because `$db` is unavailable directly in test code. ([#31](https://github.com/datex/skills/pull/31))

- **Naming and type maintenance rules are clarified.** New parameter and variable IDs use `snake_case`, while existing IDs are preserved during unrelated edits. UI components' inline type copies require a separate audit when shared interfaces change. New component IDs may be `0` or `null`; additional guidance distinguishes expression slots from plain-string placeholders and explains validation-versus-preview failures. ([#31](https://github.com/datex/skills/pull/31))

- **Footprint references cover more fulfillment and creation semantics.** New material documents order, shipment, wave, task, and operation codes; replenishment-gated picking; and shipment loading checks based on license plates. Entity ID reservation guidance explains the inclusive ceiling and dense counter requirement. Sales order line guidance distinguishes singular UI-oriented creation from batch creation with fully specified lines. Workflow guidance preserves caller-facing GUIDs on edits and deliberate legacy replacements. ([#31](https://github.com/datex/skills/pull/31))

- **Validation is an explicit gate before configuration writes.** Creator workflows now explain that configuration, datasource, and branch validation exit with errors that should be corrected before proceeding. The shared reference describes merged local/server findings and advisory warnings. It also calls out the documented exception: `dxs function validate` can exit successfully while reporting errors, so its payload must be inspected. ([#37](https://github.com/datex/skills/pull/37))

- **Branch and configuration workflows better explain ownership and lifecycle.** Organization-scoped branch selection replaces contradictory `--all-repos` examples. References cover fetching bodies by numeric ID, dependency-first write ordering, committed branches becoming read-only, round-trip verification, and save failures. Lock guidance now uses `DXS-LOCK-002` to identify foreign holders. Package-owned upserts document the explicit `--allow-external` fork path and ownership checks before editing. ([#31](https://github.com/datex/skills/pull/31), [#37](https://github.com/datex/skills/pull/37), [#41](https://github.com/datex/skills/pull/41))

- **Release-note and dependency workflows track newer CLI behavior.** Guidance now uses automatic Service Pack dependency resolution, `--extra-org`, failed-side fields, and skipped-subtree reporting. AppConfig migration notes explain connection-name matching and enum serialization variants. Version caveats identify incomplete dependency results before CLI 0.5.4 and additional organization-resolution gaps addressed in 0.5.5. ([#41](https://github.com/datex/skills/pull/41), [#44](https://github.com/datex/skills/pull/44), [#47](https://github.com/datex/skills/pull/47))

- **Authentication, traceability, and error-handling references are refreshed.** Package cascade guidance accounts for cached identities, browser sign-in, device-code fallback, and manual branch commit prompts. Examples use the canonical `dxs settings` group. CRM guidance explains result caps and description previews; DevOps requirements adds WIQL queries and truncation checks. CLI 0.5.5 notes distinguish transport failures and closed output pipes from invalid configuration or query content. ([#41](https://github.com/datex/skills/pull/41), [#47](https://github.com/datex/skills/pull/47))

- **Evaluation and contributor tooling has expanded.** Added **14 evaluation suites containing 61 scenarios**, with fixtures for component, wiring, and grid validators. An optional Claude Code component-save hook checks supported JSON files for parse errors and missing or over-100-character descriptions. A PowerShell junction installer and setup documentation were added, along with a CLI release checklist for behavior drift, generated tables, duplicated rules, and links. ([#31](https://github.com/datex/skills/pull/31), [#37](https://github.com/datex/skills/pull/37))

- **Compatibility and documentation maintenance are now explicit.** A new `compat.yaml` maps CLI version lines to skills references, initially mapping `0.5` and the default to `main`. The configuration-type table was regenerated and checked against CLI 0.5.5, including newly addressable types. Report-command navigation and cross-skill reference links were repaired, and the catalog's uncovered-type list was updated. ([#35](https://github.com/datex/skills/pull/35), [#37](https://github.com/datex/skills/pull/37), [#42](https://github.com/datex/skills/pull/42), [#44](https://github.com/datex/skills/pull/44), [#47](https://github.com/datex/skills/pull/47))
