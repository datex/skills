# fpx 0.2.0 — bundled skill, one-command skill install, app identity — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** A customer's shell agent gets everything with fpx alone: `fpx skills install` installs fpx's own CLI skill (shipped in the package) and the Agent app's skills into the folders Claude Code and Codex read; unattended agents sign in with an app identity (client secret).

**Architecture:** The fpx CLI skill moves into the fpx repo and ships in the npm package. Skill installation ports the agent-skills layout dxs uses (canonical `~/.agents/skills/<name>`, links into `~/.claude/skills` and `~/.codex/skills`, copy fallback), recorded in fpx's own `~/.fpx/skills.json`. App identity is an msal-node confidential client inside fpx. fpx never calls dxs.

**Tech Stack:** TypeScript, commander, @azure/msal-node, vitest; skills repo `npm test` harness.

**Spec/decision source:** `C:\Users\pgyoshev\.claude\plans\now-i-have-got-soft-rain.md` (Part 2, items 0, 2, 4), approved by Parvan 2026-10-08.

## Decisions
1. fpx owns its CLI skill (`skills/fpx/` in the fpx repo, in package `files`); the skills repo drops `skills/datex-studio/fpx`.
2. Layout: canonical copy `<root>/.agents/skills/<name>`, symlinks `<root>/.claude/skills/<name>` and `<root>/.codex/skills/<name>` (directory junction or copy when symlinks are refused on Windows); `<root>` = home, or cwd with `--project`; `--dir <path>` writes plain folders into one path (today's behaviour). Reference implementation to port, not call: `D:\Git\datex-studio-cli\src\dxs\core\skills\` (install layout, link/copy fallback, conflict checks).
3. fpx records its installs in `~/.fpx/skills.json` (`{ name, source: 'bundled'|'app', appUrl?, version, paths[] }`); it never overwrites a folder it did not install unless `--force`; it never reads or writes `skills-lock.json`.
4. App identity: client secret only. Env `FPX_CLIENT_ID` + `FPX_TENANT_ID` + `FPX_CLIENT_SECRET`, or `fpx login --client-id … --tenant-id … --client-secret …` stored in `credentials.yaml` as an identity of kind `app`. Token: `ConfidentialClientApplication({ auth: { clientId, authority: https://login.microsoftonline.com/<tenant>, clientSecret } }).acquireTokenByClientCredential({ scopes: [appScope] })`, cached until expiry. Source order: `FPX_TOKEN`/`FPX_TOKEN_FILE` → env app identity → active stored identity (user or app).
5. Version 0.2.0 (sync-version script); no publish, no push; the platform keeps its vendored 0.1.1.

## Review Focus
1. A skill folder with the same name already installed by something else (dxs, npx skills, hand-made) — refused with a clear FPX code unless `--force`; never silently replaced.
2. Windows without symlink privilege — falls back (junction or copy) and still works; re-running install updates both the canonical copy and the links/copies.
3. An app skill named `fpx` (or any name clashing with the bundled one) — the bundled one wins, app skill reported as skipped.
4. App identity secret never printed (status, errors, debug) and credentials file permissions applied on write (0600; owner-only ACL on Windows via `icacls`).
5. A 403 from the Agent app for an app identity — FPX-AUTH error whose suggestion names the customer-admin steps (grant `access_as_daemon`, admin consent, Manager service principal + role).
